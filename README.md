# 将 Qt 界面嵌入 CAA 对话框

## 背景

CAA 自带的对话框设计工具功能较为基础，难以实现复杂、精致的用户界面。而 Qt 在界面开发方面具有显著优势，因此本项目探索了一种方法：**将 Qt 的 UI 嵌入到 CAA 的对话框中**，从而兼顾 CAA 的业务逻辑与 Qt 的界面表现力。

------

## 环境准备（版本对照）

- 若您使用 **3DE 平台** 进行开发，安装目录下通常包含 `Qt5Plugins` 文件夹（高版本可能为 `Qt6`）。
- 请先进入该文件夹，右键任意 `.dll` 文件 → 属性 → 详细信息，查看 **产品版本** 或 **文件版本**（例如 `5.9.0.0`）。
- 根据该版本号，前往 Qt 官网下载对应的 Qt 安装包，编译器需与您的 Visual Studio 版本匹配（如 VS2015、VS2017 等）。
- 安装完成后，基础环境即配置完毕。

> **踩坑提醒**：3DE 自带的 `qmainwindow.dll` 与不同 Qt 版本可能存在兼容性问题。若 Qt 版本不匹配，会导致 `QApplication` 初始化失败，请务必确保版本严格对应。

------

## 文件结构设计

最初，我将 CAA 和 Qt 相关文件放在同一个模块下，编译可以成功。但若希望将 Qt 界面封装为独立组件，供其他模块复用，则需要将两者分离。

- 所有 Qt 相关的头文件均放置在 `publicinterfaces` 目录下，否则编译时会因找不到头文件而报错。

------

## 链接 Qt 环境（编译配置）

### imakefile 配置

在 `imakefile` 中新增 `LOCAL_LDFLAGS` 选项，包含以下内容：

- 第一个 `.lib` 文件：由 `qt_src` 编译生成，路径由 `build_qt.bat` 指定，默认位于同模块目录下的 `Object/win_b64`。
- 第二个 `libpath`：指向 Qt 安装目录中的库文件路径，例如 `xx\xx\msvc2015_64\bin`。
- `user32.lib`：系统库文件，无需额外操作。

### 插件路径设置

在桥接（bridge）文件中，我调用了 `addLibraryPath`，添加了 3DE 的插件文件夹路径。有资料指出 3DE 会自动搜索该路径，但实测注释掉后会报错，因此实际使用中建议保留此设置。
