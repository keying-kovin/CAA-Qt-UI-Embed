# Complete Implementation: Embedding Qt TreeTable into CAA Dialog

## 1. Purpose

This document describes how to port an existing Qt tree‑table widget into the CAA project `V6AddinCmdTest.m` and embed it into a `CATDlgDialog` dialog.

**Goals:**

- The outer window, title bar, and close behavior are managed by CAA's `CATDlgDialog`.
- The client area of the dialog is fully occupied by a Qt‑managed tree table.
- All existing Qt features are preserved: multi‑level headers, tree nodes, row numbers, sorting, column/row resizing, progress painting, and scrolling.
- CAA and Qt communicate only through a plain C interface and Win32 `HWND`.
- Qt sources are compiled independently; CAA's `mkmk` only links the resulting library and does not directly compile Qt headers.

This document is written for the current environment: **B421 / Qt 5.9 / MSVC2015 x64**. The PDF example uses B426 / Qt 6 / MSVC2022, but the principles are identical; only library paths, compiler versions, and Qt library names must be replaced with the actual ones.

### 3.1 Why a Plain C Interface

CAA and Qt projects should **not** expose `QWidget*`, `QTreeWidget*`, or any Qt template types directly across module boundaries because:

- CAA's header macros and compilation flags may conflict with Qt headers.
- CAA's `mkmk` may append incompatible compiler options for Qt.
- Qt classes contain meta‑objects, signals/slots, and ABI information; passing them across modules can cause link‑time and runtime issues.
- A plain C interface passes only `void*`, integers, and C strings; the CAA side does not need to know Qt internals.

Thus, CAA only calls these actions: initialize, create, resize, destroy. All tree‑table logic remains inside the Qt module.

## 5. Step 1: Define the Plain C Interface

File: `LocalInterfaces/QtTreeTableEmbed.h`

cpp

```
#ifndef QT_TREE_TABLE_EMBED_H
#define QT_TREE_TABLE_EMBED_H

#ifdef __cplusplus
extern "C" {
#endif

// Initialize Qt. Called once for the entire CAA process.
void QtEnsureInitialized(void);

// Create the tree table and embed it into the CAA window pointed by parentHwnd.
// Returns an opaque handle to the Qt object; CAA must not cast or access its content.
void *QtCreateTreeTable(void *parentHwnd,
                        int x,
                        int y,
                        int width,
                        int height);

// Resize the existing tree table.
void QtResizeTreeTable(void *handle,
                       int x,
                       int y,
                       int width,
                       int height);

// Destroy the tree table and free Qt objects.
void QtDestroyTreeTable(void *handle);

#ifdef __cplusplus
}
#endif

#endif // QT_TREE_TABLE_EMBED_H
```



### 5.1 Rationale

- `parentHwnd` is `void*` to remain C‑compatible; CAA only passes the result of `GetWindowHandle()`.
- `handle` is not a `QWidget*`; CAA cannot call Qt methods or `delete` it directly. All Qt object lifetime is managed by `QtDestroyTreeTable()`.

## 6. Step 2: Implement the Qt Independent Module

File: `qt_src/QtTreeTableEmbed.cpp`

Below is the core structure; adapt class names to your actual tree‑table implementation.

cpp

```
#include <QApplication>
#include <QCoreApplication>
#include <QTimer>
#include <windows.h>

#include "QtTreeTableEmbed.h"
#include "treetablewidget.h"

namespace {

QApplication *g_qtApplication = nullptr;
UINT_PTR g_qtEventTimer = 0;
bool g_creatingTreeTable = false;

// Win32 timer callback to pump Qt events manually.
// CAA hosts usually do not call QApplication::exec(), so without this pump,
// the tree table cannot respond to mouse or paint events.
VOID CALLBACK QtEventPumpProc(HWND, UINT, UINT_PTR, DWORD)
{
    if (g_creatingTreeTable)
        return;

    if (QApplication::instance())
        QApplication::processEvents(QEventLoop::AllEvents, 5);
}

// Use GetWindowLongPtr/SetWindowLongPtr for x64 safety.
bool PrepareAsChildWindow(HWND childHwnd, HWND parentHwnd)
{
    if (!childHwnd || !parentHwnd || !IsWindow(childHwnd) || !IsWindow(parentHwnd))
        return false;

    LONG_PTR style = GetWindowLongPtr(childHwnd, GWL_STYLE);
    style = (style & ~(WS_POPUP | WS_OVERLAPPEDWINDOW)) | WS_CHILD;
    SetWindowLongPtr(childHwnd, GWL_STYLE, style);

    LONG_PTR exStyle = GetWindowLongPtr(childHwnd, GWL_EXSTYLE);
    exStyle &= ~(WS_EX_TOOLWINDOW | WS_EX_APPWINDOW);
    SetWindowLongPtr(childHwnd, GWL_EXSTYLE, exStyle);

    SetLastError(ERROR_SUCCESS);
    HWND oldParent = SetParent(childHwnd, parentHwnd);
    if (!oldParent && GetLastError() != ERROR_SUCCESS)
        return false;

    return true;
}

} // namespace

void QtEnsureInitialized(void)
{
    if (g_qtApplication)
        return;

    QApplication *existing = qobject_cast<QApplication *>(QApplication::instance());
    if (existing) {
        g_qtApplication = existing;
        return;
    }

    // Run as a plugin to avoid Qt modifying global process state.
    QApplication::setAttribute(Qt::AA_PluginApplication, true);

#if QT_VERSION >= QT_VERSION_CHECK(5, 6, 0)
    // CAA manages DPI itself; disable Qt DPI scaling.
    QApplication::setAttribute(Qt::AA_DisableHighDpiScaling, true);
#endif

    static int argc = 1;
    static char applicationName[] = "CAAQtTreeTable";
    static char *argv[] = { applicationName, nullptr };

    g_qtApplication = new QApplication(argc, argv);

    // Use a Win32 timer to drive Qt event processing.
    g_qtEventTimer = SetTimer(nullptr, 0, 16, QtEventPumpProc);
}

void *QtCreateTreeTable(void *parentHwnd,
                        int x,
                        int y,
                        int width,
                        int height)
{
    HWND hostHwnd = static_cast<HWND>(parentHwnd);
    if (!hostHwnd || !IsWindow(hostHwnd))
        return nullptr;

    QtEnsureInitialized();
    if (!g_qtApplication)
        return nullptr;

    g_creatingTreeTable = true;

    TreeTableWidget *treeTable = new TreeTableWidget(nullptr);
    treeTable->loadDemoData();
    treeTable->setWindowFlags(Qt::FramelessWindowHint);
    treeTable->setAttribute(Qt::WA_NativeWindow, true);
    treeTable->setGeometry(x, y, width, height);

    HWND treeHwnd = reinterpret_cast<HWND>(treeTable->winId());
    if (!PrepareAsChildWindow(treeHwnd, hostHwnd)) {
        delete treeTable;
        g_creatingTreeTable = false;
        return nullptr;
    }

    // SetParent may alter Qt's internal geometry; set again.
    treeTable->setGeometry(x, y, width, height);

    // Show only after it is a WS_CHILD to avoid being recognized as a new top‑level window.
    treeTable->show();

    // Force final position via Win32.
    MoveWindow(treeHwnd, x, y, width, height, TRUE);
    ShowWindow(treeHwnd, SW_SHOW);

    g_creatingTreeTable = false;
    return treeTable;
}

void QtResizeTreeTable(void *handle,
                       int x,
                       int y,
                       int width,
                       int height)
{
    TreeTableWidget *treeTable = static_cast<TreeTableWidget *>(handle);
    if (!treeTable)
        return;

    treeTable->setGeometry(x, y, width, height);
    HWND treeHwnd = reinterpret_cast<HWND>(treeTable->winId());
    if (treeHwnd && IsWindow(treeHwnd))
        MoveWindow(treeHwnd, x, y, width, height, TRUE);
}

void QtDestroyTreeTable(void *handle)
{
    TreeTableWidget *treeTable = static_cast<TreeTableWidget *>(handle);
    if (!treeTable)
        return;

    HWND treeHwnd = reinterpret_cast<HWND>(treeTable->winId());
    if (treeHwnd && IsWindow(treeHwnd))
        SetParent(treeHwnd, nullptr);

    delete treeTable;
}
```



### 6.1 Why Not `QWindow::fromWinId()`

In this mixed CAA/Qt scenario, we avoid:

cpp

```
QWindow::fromWinId(parentHwnd);
QWidget::createWindowContainer(...);
```



because Qt's external window container may alter parent styles and child window ordering, causing issues with the CAA watchdog, coordinates, or visibility. Using raw Win32 `WS_CHILD` + `SetParent()` gives a clearer window hierarchy.

### 6.2 Why `show()` Must Come After `SetParent()`

If the Qt widget is shown before `SetParent()`, Windows treats it as an independent top‑level window. The CAA host may detect unexpected top‑level windows and trigger protective logic. By obtaining the HWND, converting to child, reparenting, and then showing, we avoid this.

## 8. Step 4: Implement Delayed Creation and Resize Synchronization

Place the following code in `UserImplementCode`:

cpp

```
TestDlg *TestDlg::s_pendingDialog = nullptr;
int TestDlg::s_retryCount = 0;
UINT_PTR TestDlg::s_retryTimer = 0;

static VOID CALLBACK QtTreeTableRetryProc(HWND, UINT, UINT_PTR, DWORD)
{
    if (!TestDlg::s_pendingDialog)
        return;

    ++TestDlg::s_retryCount;
    if (TestDlg::s_retryCount > 50) {
        KillTimer(nullptr, TestDlg::s_retryTimer);
        TestDlg::s_retryTimer = 0;
        TestDlg::s_pendingDialog = nullptr;
        return;
    }

    if (TestDlg::s_pendingDialog->TryCreateQtTreeTable()) {
        KillTimer(nullptr, TestDlg::s_retryTimer);
        TestDlg::s_retryTimer = 0;
        TestDlg::s_pendingDialog = nullptr;
    }
}

bool TestDlg::TryCreateQtTreeTable()
{
    HWND dialogHwnd = reinterpret_cast<HWND>(GetWindowHandle());
    if (!dialogHwnd || !IsWindow(dialogHwnd))
        return false;

    RECT clientRect = {};
    if (!GetClientRect(dialogHwnd, &clientRect))
        return false;

    const int margin = 8;
    const int x = margin;
    const int y = margin;
    const int width = (clientRect.right - clientRect.left) - margin * 2;
    const int height = (clientRect.bottom - clientRect.top) - margin * 2;
    if (width <= 0 || height <= 0)
        return false;

    QtEnsureInitialized();
    m_qtTreeTableHandle = QtCreateTreeTable(dialogHwnd, x, y, width, height);
    return m_qtTreeTableHandle != nullptr;
}

void TestDlg::EmbedQtTreeTable()
{
    if (m_qtTreeTableHandle)
        return;

    if (TryCreateQtTreeTable())
        return;

    // HWND may not be ready during BuildGraph; retry after the window is truly created.
    s_pendingDialog = this;
    s_retryCount = 0;
    if (!s_retryTimer)
        s_retryTimer = SetTimer(nullptr, 0, 200, QtTreeTableRetryProc);
}

void TestDlg::ResizeQtTreeTable()
{
    if (!m_qtTreeTableHandle)
        return;

    HWND dialogHwnd = reinterpret_cast<HWND>(GetWindowHandle());
    if (!dialogHwnd || !IsWindow(dialogHwnd))
        return;

    RECT clientRect = {};
    if (!GetClientRect(dialogHwnd, &clientRect))
        return;

    const int margin = 8;
    const int x = margin;
    const int y = margin;
    const int width = (clientRect.right - clientRect.left) - margin * 2;
    const int height = (clientRect.bottom - clientRect.top) - margin * 2;
    if (width > 0 && height > 0)
        QtResizeTreeTable(m_qtTreeTableHandle, x, y, width, height);
}

void TestDlg::DestroyQtTreeTable()
{
    if (s_pendingDialog == this) {
        s_pendingDialog = nullptr;
        if (s_retryTimer) {
            KillTimer(nullptr, s_retryTimer);
            s_retryTimer = 0;
        }
    }

    if (m_qtTreeTableHandle) {
        QtDestroyTreeTable(m_qtTreeTableHandle);
        m_qtTreeTableHandle = nullptr;
    }
}
```

## 15. Lifetime Design

text

```
TestDlg Constructor
  └── m_qtTreeTableHandle = nullptr

TestDlg Shown
  └── EmbedQtTreeTable()
        ├── If HWND invalid: start retry timer
        └── If HWND valid: QtCreateTreeTable()

CAA Dialog Resize
  └── ResizeQtTreeTable()

TestDlg Destructor
  └── DestroyQtTreeTable()
        ├── Stop retry timer
        ├── QtDestroyTreeTable()
        └── Clear handle
```



**Essential principles:**

- CAA never directly deletes Qt objects.
- Qt objects are destroyed by the same thread that created them (the host thread).
- The retry timer is stopped before dialog destruction.
- The Qt event‑pump timer must not access a destroyed tree table.
- If `SetParent()` fails, delete the newly created Qt control immediately to avoid orphaned windows.

We recommend logging at key points in the CAA/Qt bridge:

```

```



**Troubleshooting order:**

1. Check if CAA parent HWND is null.
2. Check if Qt successfully creates `QApplication`.
3. Check if the tree table's `winId()` is valid.
4. Check `SetParent()` return value and `GetLastError()`.
5. Check that all Qt DLLs and `qwindows.dll` are from the same version.
6. Check that `QtTreeTable.lib` is built for x64 and MSVC2015.
7. Check that CAA side did not incorrectly use `setCentralWidget()` or directly `delete` the Qt object.

## 20. Implementation Phases

### Phase 1: Embed a Blank Qt Container

Temporarily skip data loading; create only an empty `TreeTableWidget` to verify HWND, `SetParent`, display, and resize synchronization.

Rationale: Isolate window‑embedding issues from painting issues.

### Phase 2: Embed the Full Tree Table

Integrate the existing `treetablewidget.cpp` and load demo data to verify multi‑level headers, tree data, and scrolling.

Rationale: Confirm that the existing Qt control can paint and respond to events inside the CAA host.

### Phase 3: Connect Real Business Data

Replace `loadDemoData()` with a business‑data adapter, but keep the embedding interface unchanged.

Rationale: Data source changes should not affect the Qt/CAA window boundary or lifetime.

### Phase 4: Add CAA Business Callbacks

Add notifications for node selection, sorting, double‑click, or checkbox state from Qt to CAA.

We recommend adding plain C callbacks later:

cpp

```
typedef void (*QtTreeTableCallback)(int eventType,
                                    const char *nodeId,
                                    void *userData);

void QtSetTreeTableCallback(void *handle,
                            QtTreeTableCallback callback,
                            void *userData);
```



Rationale: Business callbacks also remain C ABI; CAA does not directly connect to Qt signals, avoiding exposure of Qt types across modules.
